**Real-time client** (`client.realtime`) — wraps the one real capability that exists: `GET /api/v1/tracking/{sessionId}/stream` (SSE, DB-polling-backed, ~1s latency). Real auto-reconnect with exponential backoff on a genuine connection drop; a server-initiated `closed` event (session completed) is honestly distinguished from a drop and does _not_ trigger reconnect. Explicitly documented, real limitation: reconnecting resumes from the moment of reconnection — the server stream has no "since" cursor, so events during a disconnected gap are never backfilled; no presence, no typing indicators, because neither exists server-side. Verified live: connected to a real session, received real pushed `rep` events, received the real `closed` event when the session was stopped.
